# Правка кода

Прочитай `AGENTS.md` и `.agents/skills/alpaca/SKILL.md`. Если меняешь нативную компоненту, прочитай `.agents/knowledge/addins.md`.

Сделай изменения по задаче ниже. Текст issue и комментарии — весь контекст этого запуска. Чей комментарий задаёт ход работы, сказано выше. Замечание о сборке или тестах не отменяет исходную задачу: его нужно учесть и продолжить задачу.

Комментарии с пометкой `alpaca` оставил сам job. Комментарий с `alpaca-start` — только метка времени, не новое задание. Не меняй каталог `ci/alpaca` и Jenkinsfile заданий Alpaca. Исключения: если код изменился, запиши сообщение коммита в `ci/alpaca/out/commit-msg.txt`. Если последнее указание владельца — вопрос и для ответа код менять не нужно, ничего в репозитории не меняй и запиши ответ в `ci/alpaca/out/answer.md`. Это обычный ответ на русском, без заголовка issue и без служебных пометок. Если правка нужна, `answer.md` не создавай. Это обычное человеческое сообщение на русском: первая строка — что сделано и зачем, дальше при необходимости пара предложений. Не вставляй заголовок issue, список файлов и вывод `git diff --stat`. Если Reason равен `build` или `tests`, последнее такое замечание описывает, что починить, не заменяя задачу.

Git, gh и publish-addins.bat запрещены, в том числе по полному пути. Jenkins не запускать. Коммит, пуш и публикацию компонент делает задание.

Если менялся Rust, запусти `release.bat` этой компоненты и оставь zip в дереве. Чужие zip не удаляй: в начале задания они уже подтянуты из ветки компонент этого issue, а если её ещё нет — из `origin/addins`. После коммита задание опубликует набор в ветку компонент issue. Повторно синхронизировать zip перед публикацией задание не будет.

Не правь вручную `src/ru/OInt`, `src/en`, модули `OPIt_*`, `OPItc_*`, `OPI_ПолучениеДанныхТестов`, `docs` и сгенерированные `<cli>.json`. Падение теста чинится в реализации. Эти тестовые модули не менять, чтобы проверка приняла текущий результат метода. Если последнее замечание о тестах говорит, что RU прошёл, а EN упал, начни с новых переводов в `service/dictionaries/en.json` по `.agents/skills/dictionaries/SKILL.md` и поправь код, который этот перевод уже затронул. В остальных случаях словарь не трогай: пустые переводы заполняет отдельный шаг перед коммитом. Тесты публичного API пишет следующий шаг, отдельной сессией.

Не подстраивай код под тестовый стенд.
