# Тесты публичного API

Это отдельная сессия. Реализацию уже сделал другой запуск. Его ход рассуждений сюда не входит: ниже только задача, комментарии и diff.

Прочитай в `AGENTS.md` разделы «Соглашения по тестовым модулям», «Реестр и функции проверок» и «Правила именования». Форму спорного теста бери из уже существующих тестов того же модуля.

Публичный API — экспортные методы модулей `OPI_*` в `src/ru/BSL/OpenIntegrations`: новый метод, изменённая сигнатура или поведение, которое видит пользователь библиотеки. Внутренняя деталь запроса при том же внешнем методе публичным API не считается.

Если такого изменения нет, файлы не трогай.

Если оно есть, для каждого такого метода добавь или поправь тесты под контракт задачи и описание метода. Форму бери из соседнего теста того же модуля.

1. Найди область метода в `OPI_*`.
2. В `OPIt_*` найди запускаемый тест этой области. Если его нет, создай по образцу модуля и зарегистрируй в `ПолучитьТаблицуТестов`. Для нового модуля добавь константу секции, `.mdo`, регистрацию в конфигурации тестов и запись в `ПолучитьСоответствиеРазделовТестирования`.
3. Атомарный тест называется `<МодульБезПрефикса>_<Метод>` и лежит в `АтомарныеТесты`.
4. В нём до `//END` есть один вызов `Обработать` с пустым `Вариант`. Функция `Проверка_<имя теста>` лежит в `OPI_ПолучениеДанныхТестов` и не вызывает методы `OPI_*`. Другие сценарии того же метода идут отдельными вызовами `Обработать` с заполненным `Вариант` после `//END`.
5. Объект, созданный в одном тесте и нужный другому, передаётся параметром `Обработать`, а не общим служебным методом.

Менять можно только:

- модули `OPIt_*` в `src/ru/BSL/Tests`;
- записи и функции `Проверка_*` в `OPI_ПолучениеДанныхТестов`;
- `.mdo` нового тестового модуля и его регистрация в конфигурации тестов, если модуля ещё не было.

Подгонять тест под текущий код запрещено. Ожидаемое значение, текст ошибки и условие проверки берутся из задачи и из описания метода. Если метод возвращает другое, тест остаётся про задачу: не ослабляй проверку и не подставляй в неё фактический результат вызова. Diff реализации ниже показывает, какой метод изменился, и не является источником ожидаемого результата.

Реализацию в этом запуске не менять: ни `OPI_*` в `src/ru/BSL/OpenIntegrations`, ни Rust, ни `src/ru/OInt`, ни `src/en`, ни `OPItc_*`, ни `service/dictionaries`, ни `docs`.

Git, gh и publish-addins.lua не вызывать. Jenkins не запускать. Каталог `ci/alpaca` и Jenkinsfile заданий Alpaca не менять, кроме одной строки в `feelings.txt` своего агента. Если тесты всё же изменились, поправь уже записанный `ci/alpaca/out/commit-msg.txt`, чтобы сообщение описывало и их. Если файлы не трогал, сообщение не меняй. Код под тестовый стенд не подстраивать.
