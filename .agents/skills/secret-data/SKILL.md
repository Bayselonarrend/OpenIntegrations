# Секреты тестов

Учётные данные тестов лежат в `data.sqlite.gpg` в корне репозитория. Пайплайн расшифровывает его в `data.sqlite` фразой из Jenkins credentials `gpgkey` и переменной `GPGKEY`. Тесты читают таблицу `test_params`: колонки `key`, `value`, `type`. `type` — `String` или `Number`. Имя параметра в коде — это `key`, его берёт `ПолучитьПараметр`.

В git попадает только `data.sqlite.gpg`. `data.sqlite` в `.gitignore`. Открытый файл после правки не коммитить.

Фраза передаётся переменной `GPGKEY`. В задание Полины Jenkins её уже кладёт. Локально задай ту же переменную перед запуском. В чат, комментарий, сообщение коммита и `feelings.txt` фразу и значения параметров не писать. В комментарии достаточно имени ключа: какой параметр изменён.

Скрипт: `lua ci/secret-data.lua` из корня репозитория. Нужны `gpg` и `sqlite3` в `PATH`. Шифр тот же, что у пайплайна: симметричный AES256.

## Команды

Список имён и типов, без значений:

```
lua ci/secret-data.lua keys
```

Расшифровать, записать значение и зашифровать обратно. Значение команды `set` приходит из stdin, не аргументом.

```
lua ci/secret-data.lua decrypt
lua ci/secret-data.lua set RPortal_Token < new-value.txt
lua ci/secret-data.lua encrypt
```

Числовой параметр: `lua ci/secret-data.lua set SomeCount Number`.

`get KEY` печатает текущее значение. Оно нужно только чтобы сверить правку. В комментарий и сообщение коммита его не переносить.

Несколько параметров меняются между одним `decrypt` и одним `encrypt`. Без `encrypt` в репозитории остаётся прежний `data.sqlite.gpg`.
